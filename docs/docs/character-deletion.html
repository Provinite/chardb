Character Deletion & Species Removal

A walkthrough of the community admin tools for managing characters

0

Overview

Community admins and moderators now have two new character management tools: Delete Character and Remove from Species. Both sit in the ⋯ menu on the character page and on every card in the Trait Review Queue, one deliberate step away from the everyday buttons, and both ask you to confirm.

🗑️

Delete Character

Deletes the character and removes it from all public views.

↩️

Remove from Species

Detaches the character from its species, preserving trait data as custom fields.

🛡️

Permission-gated

Requires the canDeleteCharacter role permission or global admin.

📋

Queue integration

Both actions are in the menu on each Trait Review card.

1

The staff menu on the character page

Edit Character is a button in the character info section, for the owner and for staff alike. Beside it, staff with the canDeleteCharacter or canEditCharacterRegistry permission (or global site admins) get a ⋯ button. It opens a Staff actions menu:

  • Remove from Species — detaches the character from its species (only shown when the character has a species assigned)
  • Delete Character — deletes the character

An owner without either permission sees Edit Character and no menu.

Note: The menu only appears while the character is viewed in a community context (i.e., the character belongs to a species within your community). A character that has already been removed from its species offers no Remove from Species.
Character page viewed as a moderator, with the ⋯ menu open beside Edit Character
2

Deleting a character

Choosing Delete Character from the menu shows a confirmation dialog describing what will happen. Focus starts on Cancel, so a stray Enter does nothing:

  • The character is deleted and hidden from all public views.
  • Any pending trait reviews for the character are cancelled.
  • After confirmation you are redirected to the character browse page.
Important: This action is not self-service reversible. Use it for characters that violate community rules or are otherwise no longer appropriate.
The delete confirmation. Undoing it takes a site admin
3

Removing a character from its species

Choosing Remove from Species from the menu shows a confirmation dialog. There is no undo, so Remove stays disabled until you type the character's name exactly. The operation:

  • Clears the character's species, variant, registry ID, and trait values.
  • Preserves the trait data — all existing trait values are flattened into the character's custom fields (e.g., Eye Color → Amber becomes a custom field entry) so no information is lost.
  • Cancels any pending trait reviews for that character.
  • The character remains visible on its owner's profile and in global browse — it simply no longer appears under the species in the community.
Tip: Use this action when a character was registered to a species in error, or when the owner requests removal from the species registry without losing their character entirely.
Remove stays disabled until the name is typed in full
After removal: the character's Eye Color trait value ("Amber") is preserved as a custom field — no data is lost
4

Actions in the Trait Review Queue

Both actions are also on each card in the Trait Review Queue, in the ⋯ menu at the right-hand end of the card's buttons. This lets moderators handle problematic submissions without leaving the queue, while keeping them away from Approve.

  • Approve — confirms the proposed trait values (a button on the card)
  • Remove from Species (menu) — kicks the character from the species, flattening its traits to custom fields and removing the review entry from the queue
  • Delete (menu) — soft-deletes the character, which also cancels the pending review and removes it from the queue

Both open the same confirmation dialogs as on the character page.

Tip: The Reject button (for sending the character's traits back to the previous approved state) is still available for cases where you want to roll back values without removing the character from the species.
A Trait Review card with its ⋯ menu open, at the opposite end of the row from Approve
5

Setting up the permission

The two actions use different permissions:

  • Delete Character requires the canDeleteCharacter permission. Enable the Delete Characters toggle on any role you want to grant this ability.
  • Remove from Species requires the canEditCharacterRegistry permission (the same permission used for editing registry IDs and trait values). Enable the Edit Any Character (Registry) toggle.

Go to Community Settings → Permissions → Role Management, open the role you want to configure, and toggle the appropriate permissions. Save the role — changes apply immediately to all members with that role.

Default roles: The Admin role created automatically when a new community is started includes both canDeleteCharacter and canEditCharacterRegistry by default. Moderator and Member roles do not have canDeleteCharacter; Moderator has canEditCharacterRegistry.
