Email Verification

An account opens when its address answers

0

Overview

Signing up used to hand back a session immediately, and nothing ever checked that the address on the account belonged to the person holding it. Now signup sends a link and nothing else: the account exists, and stays shut until somebody follows that link.

The reason is deliverability, not ceremony. Mail to a typo'd address bounces on every send, and a stranger who never signed up reports it as spam rather than hunting for an unsubscribe link. Both attach to the sending domain. There is a security half too: whoever really owns a mistyped address would otherwise receive that account's password resets.

✉️

One link

Single use, good for 24 hours, sent the moment you sign up.

🔒

No session first

Signing in is refused until the address answers.

Six, ever

The hard ceiling on how much mail one address can receive.

Everyone who already had an account is confirmed. Nobody is asked to answer a message they never had the chance to receive. The gate applies from here on.
1

Signing up

The form is unchanged — invite code, username, address, password. What changes is where it lands.

The signup form, filled in and ready to submit.
Where signup ends now: a card naming the address, not the dashboard.
The address is shown back to you. A typo is the most likely reason the email never arrives, and it is invisible the moment the form clears — so the confirmation names what it sent to.
2

The email

One button and the same link in plain text underneath, for the mail clients that will not render the button.

The delivered message, in MailHog. No settings footer: this one cannot be opted out of.

The link carries the token as the last path segment:

https://chardb.cc/verify-email/98d8c8e09858159e55d9eb76555852a473bb02233c0db34773df09d76ee96e21

The token is 32 random bytes written as hex, which matters for two reasons. Only its SHA-256 is stored, so the database cannot give the link back to anybody who reads it — including us. And hex has no . in it: a dot in the last path segment makes the single-page app's history fallback skip its rewrite, and the page would 404 before it ever loaded.

3

Trying to sign in first

The password is checked first and the refusal comes after it, so the login form cannot be used to find out which addresses have accounts. Get the password wrong and you are told the credentials are wrong, whatever state the account is in.

The right password, an unconfirmed address, and a way out.
Resending says the same thing to everyone. An address nobody registered, one already confirmed, and one that has used up its allowance all get the same answer: if that address still needs confirming, a new link is on its way. Anything more definite would be a way to test whether somebody has an account here.
4

Following the link

The page redeems on load rather than behind another button — the token is already in the URL, so a button would only add a step.

Done. The account can sign in from here on.
Clicking twice is fine. Mail clients and corporate link scanners fetch URLs before a human ever clicks, so a single-use token is routinely spent by a machine. Following an already-redeemed link for an account that is confirmed reports success — because that is the truth about the account.
5

When the link doesn't work

Links last a day. An expired one, a spent one on an account that is still unconfirmed, and one that was never minted all end here.

A link that no longer opens anything, and where to go next.

The way out is the login screen: the right password on an unconfirmed account produces the resend offer from step 3.

6

Six emails, ever

A feature that mails an address on request is a feature somebody can point at a stranger. So there is a ceiling, and it is a lifetime count rather than a window — a window resets, and a script is happy to wait.

  • Six per address, ever. Signup spends one, leaving five resends. Counted on the address, not the account, so deleting one and registering again does not hand out a fresh six.
  • Three per fifteen minutes, so all of them cannot arrive at once because somebody leant on the button.

The reach is narrower than it looks. An address can only ever be registered once, so signup spends at most one of the six; and a resend for an address with no unconfirmed account behind it sends nothing at all. There is no way to put mail in the inbox of somebody who never signed up.

If an address genuinely never receives. Six attempts is the end of the automatic road. An administrator can mark the account confirmed by hand — the same backstop that covers a mailbox which silently drops everything we send it.
